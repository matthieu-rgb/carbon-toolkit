# CARBON v0.5 — Client Web + carte de surface d'attaque — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a localhost Web client (Starlette, same process/Session as the MCP server) that renders a live attack-surface map and drives Libre-mode tools by click, with destructive actions gated by the existing human-approval authority surfaced as a Web modal.

**Architecture:** A new `carbon.web` package exposes a Starlette app that mounts the existing MCP streamable-HTTP sub-app under `/mcp` (Bearer-guarded) beside Web UI+API routes under `/` (cookie-guarded). Both share one `Session` and one `ApprovalQueue`. The map is a pure projection `build_surface(history)` added to `session.state()`; the browser gets live state over SSE and sends actions by POST. No new execution path: every tool run still goes through `Session.run_tool` → `execute_tool`.

**Tech Stack:** Python ≥3.11, Starlette (already transitive via `mcp==2.3.0`), uvicorn==0.54.0, SSE hand-rolled (`StreamingResponse`), vendored cytoscape.js (no CDN), httpx (dev/test ASGI client). Tests use python-can `interface="virtual"` + the simulated ECU; no real browser.

**Spec:** `docs/superpowers/specs/2026-11-19-carbon-design.md` — §5.8 and **§5.8.1** (the ten build decisions) are binding. Read both before starting.

## Global Constraints

- **Règle d'or :** the methodology engine contains no tools, the tool registry no methodology; `carbon/core/surface.py` is a pure view (no methodology, no tool, no mutable state). Every tool run goes through `Session.run_tool` → `execute_tool` — the Web executes nothing itself.
- **AC-10 inviolable :** a destructive action of `Origin.WEB` → `pending-approval`, blocks, approved only through a human channel (Web modal). `assume_yes`/`--yes` is **ignored** for `Origin.WEB` (the Web API must not even accept an `assume_yes` field). An AI holding the MCP Bearer token must be unable to call any Web API route or resolve any approval.
- **Localhost only :** bind `127.0.0.1`; reject any other bind. Validate `Origin`/`Host` headers (anti-CSRF / anti-DNS-rebinding). Web auth is a **distinct token** from MCP, delivered via a one-time bootstrap URL exchanged for an `HttpOnly` + `SameSite=Strict` cookie. The token/secret is stored outside the repo (mkstemp O_EXCL 0600, like the MCP token).
- **No AI attribution anywhere** — no `Co-Authored-By`, no "Generated with …" in commits, PR body, code comments or docs. (Technical mentions like "Claude Desktop as an MCP client" are domain content and fine.)
- **Design must NOT look AI-generated.** No generic template look (no purple/indigo gradient hero, no emoji-sprinkled headings, no default Tailwind palette). Do real design research first (SavvyCAN, Wireshark, Burp Suite, Ghidra, caring-caribou, metasploit console) and follow the `frontend-design` skill: a deliberate, professional security-tool aesthetic, legible for a beginner (labels, legend) yet dense and keyboard-navigable for an expert. Serve both audiences (project is for beginners *and* experts).
- **When blocked, research the web** (versions, licences, security best practices, SSE-under-ASGI test patterns) rather than guessing.
- Python ≥3.11, SPDX header `# SPDX-License-Identifier: GPL-3.0-or-later` on every new `.py`. Dependencies pinned and proven by a test import. Vendored JS/CSS pinned by version with its licence file committed (GPL upstream audit).

## Review Focus

- **MCP token must not reach Web routes.** A request carrying only the MCP Bearer token (no Web cookie) to `/api/*` or `/api/approvals/*` must be rejected. Test in Task 4/7.
- **Cross-origin / wrong Host POST is refused.** A POST with a foreign `Origin` or an unexpected `Host` header is rejected before the tool runs (DNS-rebinding defence). Test in Task 4.
- **`assume_yes` cannot bypass approval from the Web.** A Web tool POST that smuggles `assume_yes`/`--yes` still blocks a destructive action on approval. Test in Task 5/6.
- **SSE never hangs a test and fails closed.** No connected browser ⇒ destructive action times out to refusal; a reconnecting browser replays outstanding approvals. Tests read a bounded number of SSE events with a timeout, never an open-ended stream. Task 6.
- **`build_surface` on degenerate history.** Empty history, a failed `uds_security_access` (must NOT show unlocked), an NRC-rejected session, duplicate discoveries (monotonic, no duplicate nodes), history truncated at `history_limit`. Task 2.
- **Concurrent runs serialize.** Two simultaneous `run_tool` calls (e.g. Web + MCP) never interleave on one bus; history stays consistent. Task 1.

## Task 2: Attack-surface projection — `build_surface`

**Files:**
- Create: `carbon/core/surface.py`
- Modify: `carbon/core/session.py` (`state()` gains a `"surface"` key)
- Test: `tests/core/test_surface.py`

**Interfaces:**
- Consumes: the `history` list of `ToolResult` (via `state()`), each `ToolResult.to_dict()` with keys `tool, ok, summary, data, …`. Known `data` shapes: `can_sniff → {"frames": [{arbitration_id, extended, data, timestamp}, …]}`; `uds_scan → {"supported": ["0x27", …], "unsupported": [...]}`; `uds_session → {"session": "extended", "nrc"?}`; `uds_security_access → {"unlocked": bool, "level": int, "seed", "nrc"?}`; `uds_read_dtc → {"dtcs": [...], "nrc"?}`; `can_inject → {"arbitration_id": int, …}`.
- Produces: `build_surface(history: list[dict], *, channel: str, current_tool: str | None = None) -> dict` returning `{"nodes": [...], "edges": [...], "current": <node id | None>, "session": {"active": str|None, "unlocked": bool}}`. `history` is the list of `ToolResult` dicts (as in `state()["history"]`). Node schema: `{"id","type","label", "state"?, "parent"?}` with `type ∈ {"bus","ecu","service","level","dtc"}`. The ECU id uses the responder arb-id convention `0x7E8` (`ecu:0x7e8`) when UDS results exist; CAN-only frames attach ECU nodes per observed `arbitration_id`.

- [ ] **Step 1: Write failing tests** (`tests/core/test_surface.py`):
  - `test_empty_history_has_bus_only`: empty history → one `bus:<channel>` node, no ecu/service, `current=None`, `session={"active":None,"unlocked":False}`.
  - `test_sniff_adds_ecu_nodes`: a `can_sniff` result with two arb-ids → two `ecu:*` nodes under the bus, each with an edge.
  - `test_scan_adds_service_nodes`: a `uds_scan` with `supported=["0x27","0x22"]` → two `service:*` nodes parented to the UDS ECU.
  - `test_session_sets_active`: a successful `uds_session` → `session.active == "extended"`; an NRC-rejected one (`ok=False`) leaves `active=None`.
  - `test_failed_security_access_not_unlocked`: `uds_security_access` with `data.unlocked=False`/`ok=False` → `session.unlocked == False`; a successful one → a `level:*` node `state="unlocked"` and `session.unlocked == True`.
  - `test_monotonic_no_duplicate_nodes`: the same `uds_scan` twice → services appear once.
  - `test_current_is_last_successful`: `current` is the node id derived from the last `ok=True` result (bus/ecu/service as applicable); a trailing failed result does not move `current`.
- [ ] **Step 2: Run — expect failure.**
- [ ] **Step 3: Implement `build_surface`** as a pure fold: iterate `history` in order, accumulate a dict of nodes keyed by id (monotonic), update `session` state fields from the latest relevant `ok=True` result, derive `current`. No imports from methodology or tools. Then in `session.state()`, add `"surface": build_surface([r.to_dict() for r in self.history], channel=self.channel, current_tool=<last tool>)`. (Reuse the already-built history dicts to avoid double serialization.)
