# CARBON v0.3 — Serveur MCP + IA branchable — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exposer le cœur CARBON (les 10 adaptateurs existants + état de session + journal) en **serveur MCP** pilotable par n'importe quel client/modèle, avec un garde-fou destructif à file `pending-approval` approuvée **hors du pipe MCP**.

**Architecture:** On **enveloppe** le SDK MCP Python (`MCPServer`, SDK `mcp` 2.x) sans le réécrire (règle d'or). Un pipeline d'exécution partagé (`execute_tool`) devient le **chemin unique** garde-fou → `run()` → journal, invoqué à la fois par la CLI (origine `CLI`) et par le serveur MCP (origine `MCP`). Une `Session` en mémoire, propriété du process serveur, tient le bus/journal fixés au lancement et l'historique des derniers résultats ; la CLI historique reste un process court et indépendant qui ne partage que le journal JSONL. Les actions destructrices d'origine MCP passent par une `ApprovalQueue` bloquante approuvée sur la **console du serveur** (mode HTTP+token) ; en mode stdio (console = pipe protocole) le destructif est refusé.

**Tech Stack:** Python ≥3.11, SDK MCP Python **`mcp==2.3.0`** (épinglé en Task 1 ; API 2.x : serveur `from mcp.server.mcpserver import MCPServer`, client en mémoire `from mcp import Client` — **pas** `FastMCP`, qui était le nom 1.x), `python-can` (bus `virtual` en test), `udsoncan`/`can-isotp` (déjà là), `click`, `pytest`, `threading` (Event, pas de `sleep`).

**Spec:** `docs/superpowers/specs/2026-11-19-carbon-design.md` — autorité : **§5.4.1 « Périmètre v0.3 »** (+ §5 règle d'or, §5.1 cœur, §5.3 adaptateurs, §5.4 serveur MCP, §6 sécurité, §8 lignes v0.3, §9 roadmap v0.3, §10 O6/AC-10).

## Global Constraints

- **En-tête licence** sur chaque fichier `.py` : `# SPDX-License-Identifier: GPL-3.0-or-later`.
- **Python ≥ 3.11.** `from __future__ import annotations` en tête (cohérent avec l'existant).
- **Règle d'or** : le serveur enveloppe le SDK MCP ; il ne contient **aucune méthodologie** et **n'exécute un outil QUE via le registre d'adaptateurs existant et `execute_tool`** — aucun chemin d'exécution parallèle à la CLI.
- **SDK MCP épinglé, jamais supposé.** Fait en **Task 1** : `mcp==2.3.0`, API prouvée par test. **Snippet canonique de référence** (imports, décorateurs, client en mémoire async) dans `.superpowers/sdd/2026-11-22-carbon-v0.3-mcp/task-1-report.md` — les Tasks 5/6/8 s'en servent tel quel. API 2.x : `MCPServer` (pas `FastMCP`), `@server.tool()` / `@server.resource(uri)`, client `from mcp import Client` piloté via `asyncio.run(...)` (le projet n'a pas `pytest-asyncio` ; plugin `anyio` présent).
- **Contrat de surface d'erreur** (inchangé v0.2) : un échec applicatif (NRC, refus) → `ToolResult(ok=False)` informatif, **jamais** levé ; seules les erreurs transport/timeout lèvent (dans les adaptateurs). `execute_tool` **capture** `BusError`/`UdsError`/`ValueError`/`OSError` en `ToolResult(ok=False)` journalisé.
- **Garde-fou destructif** : une action destructrice d'**origine MCP** part **toujours** en `pending-approval`, **bloque**, et n'exécute qu'après approbation **humaine** ; `--yes` est **ignoré** pour l'origine MCP ; **stdio refuse** le destructif ; **timeout → refus** journalisé. `--yes` ne vaut que pour l'origine CLI.
- **Journal** : chaque action (CLI ou MCP) journalisée ; `actor = "mcp"` pour l'origine MCP, `"cli"` pour la CLI.
- **Synchronisation par `threading.Event`, jamais `time.sleep`** (leçon flaky v0.1).
- **Tests sans matériel** : bus `interface="virtual"` (pas de socketcan en CI/dev macOS). **Aucun modèle ni réseau en CI** : O6 prouvé par un **client MCP en mémoire** fourni par le SDK.
- **Réseau** : HTTP **bind `127.0.0.1`** + **token Bearer** généré au lancement, stocké **hors dépôt**.
- Adapters, signatures et comportements existants (`carbon/core/*`, `carbon/tools/*`, `carbon/emu/*`, `carbon/uds/*`) **ne sont pas modifiés** sauf la refonte explicite de `carbon/cli.py` (Task 7) sur `execute_tool`.

## Review Focus

- **Course d'approbation / double résolution** : deux résolutions console pour le même id, ou une résolution arrivant **après** le timeout, ne doivent ni ré-exécuter l'action ni crasher. → testé Task 3 (et e2e Task 6).
- **Réactivité du serveur pendant une attente** : un appel MCP **non destructif** doit répondre pendant qu'un appel destructif **bloque** (le blocage ne gèle pas le serveur). → testé Task 6.
- **L'IA ne peut pas s'auto-approuver** : un appel destructif d'origine MCP part en `pending-approval` **même** avec `assume_yes=True` / tout « token » détenu par l'appelant. → testé Task 2 (unitaire) + Task 6 (e2e).
- **stdio + outil destructif** : refus **clair et immédiat** (pas de blocage infini sans console). → testé Task 6/8.
- **HTTP sans / avec mauvais token Bearer** : rejeté ; bind limité à `127.0.0.1`. → testé Task 8.

## Contrat MCP de CARBON (référence partagée — exacte, verbatim)

**API SDK (`mcp==2.3.0`, prouvée Task 1 ; détails dans task-1-report.md) :**
```python
from mcp import Client                       # client en mémoire
from mcp.server.mcpserver import MCPServer   # serveur (ex-FastMCP en 1.x)
server = MCPServer("carbon")
@server.tool()                               # renvoyer dict[str, Any] (bare `-> dict` => pas de structured_content)
def uds_scan() -> dict[str, Any]: ...
@server.resource("carbon://journal")
def journal() -> str: ...
# Test (async, via asyncio.run(run())) :
async with Client(server) as client:
    tools = await client.list_tools()        # tools.tools[i].name
    r = await client.call_tool("uds_scan", {})  # r.structured_content, r.content[0].text (JSON), r.is_error
    res = await client.read_resource("carbon://journal")  # res.contents[0].text
```

**Enums d'exécution** (`carbon/core/execute.py`) :
- `class Origin(enum.Enum): CLI = "cli"; MCP = "mcp"` — `origin.value` est l'`actor` du journal.
- `class Decision(enum.Enum): APPROVED = "approved"; DENIED = "denied"; TIMEOUT = "timeout"`.
- `class ActionRefused(Exception)` — refus destructif **côté CLI** (non journalisé, la CLI le présente).
- `class Approver(typing.Protocol): def request(self, tool: str, params: dict) -> Decision: ...`

**Outils MCP (10, = les adaptateurs ; schéma typé exposé, miroir de la surface CLI `_PARAMS`).** Les kwargs non exposés par la CLI (`rxid`/`txid`) **restent à leurs défauts** et n'apparaissent **pas**. `channel`/`interface`/`journal` sont **de niveau session** (lancement serveur), **jamais** par outil. Chaque outil renvoie `ToolResult.to_dict()`.

| Outil MCP | Signature exposée | Destructif |
|---|---|---|
| `can_sniff` | `(count: int \| None = None, timeout: float = 1.0)` | non |
| `can_dump` | `(path: str, count: int \| None = None, timeout: float = 1.0)` | non |
| `can_replay` | `(path: str)` | **oui** |
| `can_inject` | `(arb_id: int, data_hex: str = "", extended: bool = False)` | **oui** |
| `uds_scan` | `()` | non |
| `uds_session` | `(session: str = "extended")` | non |
| `uds_security_access` | `(level: int = 1)` | non |
| `uds_read_did` | `(did: int = 0xF190)` | non |
| `uds_read_dtc` | `(status_mask: int = 0xFF)` | non |
| `uds_clear_dtc` | `(group: int = 0xFFFFFF)` | **oui** |

- `can_inject` : `data_hex` est décodé en octets par le wrapper (`bytes.fromhex`) ; l'adaptateur reçoit `data=<bytes>`. Documenter « payload hex, ≤ 8 octets ».
- Outils destructifs = **`can_replay`, `can_inject`, `uds_clear_dtc`** (= `adapter.destructive`).

**Surface état/session** — outil `session_state() -> dict` :
`{"tools": [<noms>], "methodology": {"mode": "libre", "loaded": false}, "history": [<ToolResult.to_dict() des N derniers>], "channel": <str>, "interface": <str>}`.

**Ressource** — URI `carbon://journal` → **texte JSONL brut** du journal de session (lecture seule). Pas de rapport formaté (v1.0).

**Pas de surface d'approbation en MCP** : l'approbation est **hors pipe MCP** (console). Un appel destructif bloque jusqu'à résolution/timeout, puis renvoie le `ToolResult` (exécuté) ou un `ToolResult(ok=False)` (refus/timeout).

**Actor journal** : `"cli"` (origine CLI) / `"mcp"` (origine MCP).

### Task 2: `Origin` + pipeline d'exécution partagé `execute_tool`

**Files:**

**Interfaces:**
- Consumes: `Adapter`, `ToolResult`, `Journal`, `authorize` (existants).

  - `def execute_tool(adapter: Adapter, params: dict, *, origin: Origin, journal: Journal, assume_yes: bool = False, interactive: bool = False, approver: Approver | None = None, prompt_fn=input) -> ToolResult`
- Contrat de `execute_tool` :
  - **Garde** : si `adapter.destructive` —
    - `origin is Origin.CLI` → `authorize(adapter, assume_yes=assume_yes, interactive=interactive, prompt_fn=prompt_fn)` ; si refusé → **lève `ActionRefused`** (non journalisé).

  - **Journal** : journaliser le `result` (succès ou échec) **une fois**, `actor = origin.value`.
  - **Retour** : le `ToolResult`.

### Task 3: `ApprovalQueue` bloquante + approbateur console

**Files:**
- Create: `carbon/mcp/approval.py`
- Test: `tests/mcp/test_approval.py`

**Interfaces:**
- Consumes: `Decision` (de `carbon.core.execute`).
- Produces :
  - `@dataclass class PendingApproval: id: str; tool: str; params: dict` (+ interne : `Event`, `Decision | None`).
  - `class ApprovalQueue:`
    - `__init__(self, timeout: float = 300.0)`
    - `request(self, tool: str, params: dict) -> Decision` — enregistre un `PendingApproval` (id court unique, p. ex. `secrets.token_hex(2)`), **bloque** sur son `Event` jusqu'à `timeout` ; retourne la `Decision` posée, ou `Decision.TIMEOUT` à l'expiration ; retire l'entrée de la file à la sortie. **Implémente `Approver`.**
    - `pending(self) -> list[PendingApproval]` — snapshot thread-safe des attentes.
    - `resolve(self, approval_id: str, decision: Decision) -> bool` — pose la décision et réveille le `request` bloqué ; `True` si trouvé, `False` sinon (id inconnu **ou déjà résolu/expiré** — **jamais** de double exécution ni d'exception).
  - `class DenyingApprover:` `request(...) -> Decision` renvoie toujours `Decision.DENIED` (approbateur du mode stdio).
  - `def console_resolve(queue: ApprovalQueue, line: str, *, out=print) -> None` — parse une ligne opérateur (`list` ; `approve <id>` ; `deny <id>`) et appelle `queue.pending()`/`queue.resolve(...)`. Testable sans stdin réel.
- Thread-safety : un `threading.Lock` protège la table des attentes.

  - `test_resolve_after_timeout_returns_false` (résoudre une entrée déjà expirée → `False`).
