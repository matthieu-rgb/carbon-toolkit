# CARBON v0.2 — UDS + ECU simulée — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Donner à CARBON un dialogue UDS (ISO 14229) complet — scan de services, sessions, seed-key, lecture/effacement de DTC, lecture de DID — testable **sans matériel** contre une **ECU simulée** embarquée, sur `vcan0`.

**Architecture:** Deux couches nouvelles, découplées (règle d'or du design §5). Côté *client*, une couche UDS (`carbon/uds/`) qui enveloppe `can-isotp` (transport ISO 15765-2, implémentation pure-Python `isotp.CanStack`) + `udsoncan` (client ISO 14229) et expose six adaptateurs `Adapter` renvoyant des `ToolResult`. Côté *cible*, une ECU simulée (`carbon/emu/`) : un répondeur ISO-TP/UDS maison (udsoncan ne fournit pas de serveur) qui gère sessions, sécurité, DTC et seed-key, lancé par `carbon emu start`. Tout tourne sur le bus `virtual` de python-can en test et sur `vcan0` en conteneur — jamais l'ISO-TP noyau (socketcan) — ce qui tient AC-07.

**Tech Stack:** Python ≥ 3.11, `python-can`, `can-isotp` (import `isotp`), `udsoncan`, `click`, `pytest`. Réutilise `carbon.core` (ToolResult, Adapter, Registry, Journal, authorize) et `carbon.can.bus` (open_bus) de v0.1 **sans les modifier**.

**Spec:** `docs/superpowers/specs/2026-11-19-carbon-design.md` (périmètre v0.2 = **Option A**, §5.6.1 ; critère AC-03 + AC-07 ; garde-fou destructif §6).

## Global Constraints

- **Licence/en-tête** : chaque nouveau `.py` commence par `# SPDX-License-Identifier: GPL-3.0-or-later` puis un docstring d'une ligne. `from __future__ import annotations` en tête de module.
- **Contrat de sortie inchangé** : chaque outil est un `Adapter` (classe avec `name: str`, `destructive: bool`, `run(self, **params) -> ToolResult`) et renvoie un `ToolResult` construit en kwargs (`tool, ok, summary, started_at, ended_at, data, artifacts`). `started_at`/`ended_at` = `datetime.now(timezone.utc)`.
- **NRC = résultat informatif, pas une erreur** : une réponse négative UDS (ECU qui refuse : service non supporté, DID inconnu, accès refusé, mauvaise clé…) se traduit par `ToolResult(ok=False, …)` avec le **nom et le code** du NRC dans `summary`/`data`. Un adaptateur **ne lève jamais** pour un NRC. Seules les **pannes de transport/timeout** lèvent une `UdsError` (la CLI l'attrape comme `BusError`).
- **Sans matériel** : toute la couche s'exécute sur un bus python-can `virtual` (tests) ou `vcan0` (conteneur), via l'ISO-TP **pure-Python** (`isotp.CanStack`). Interdiction d'utiliser l'ISO-TP noyau socketcan (dépend du matériel/kernel).
- **Réutilisation du bus** : la couche UDS ouvre son bus CAN sous-jacent via `carbon.can.bus.open_bus(channel, interface)` (remédiation et erreurs déjà gérées en v0.1).
- **Versions épinglées** : `udsoncan` et `can-isotp` ont un historique de ruptures d'API entre elles. L'implémenteur **épingle dans `pyproject.toml` les versions exactes qu'il a validées** (`udsoncan==X.Y.Z`, `can-isotp==X.Y.Z`) et les note dans son rapport. Ne pas laisser non épinglé.
- **Synchronisation des tests** : attendre la **disponibilité** de l'ECU via un `threading.Event` exposé par `start()` — **jamais** de `time.sleep` fixe (le bus virtuel perd les trames avant que le récepteur existe ; leçon v0.1, cf. commit 954afd8).
- **Adressage par défaut** : CAN 11-bit normal, ECU en requête `0x7E0` / réponse `0x7E8`. Du point de vue client : `txid=0x7E0` (émission), `rxid=0x7E8` (réception) ; l'ECU prend le miroir.
- **Garde-fou destructif** : `uds_clear_dtc` a `destructive = True` ; la CLI le passe par `authorize(...)` exactement comme `can_inject`/`can_replay` en v0.1. Les cinq autres adaptateurs UDS sont non destructifs.
- **Seed déterministe en test** : l'ECU accepte un seed fixe en configuration pour la reproductibilité des tests ; en exécution réelle le seed peut être par défaut fixe et documenté (pas de la vraie crypto).

## Review Focus

- **Aucun répondeur sur le bus** : un client UDS qui ne reçoit pas de réponse doit lever `UdsTimeoutError` de façon **bornée** (pas de blocage infini, pas de traceback brut). → test Task 2.
- **NRC renvoyé par l'ECU** : l'adaptateur renvoie `ToolResult(ok=False)` nommant le NRC et la CLI sort en code ≠ 0 proprement, sans traceback. → tests Tasks 4 et 6.
- **`clear_dtc` non interactif sans `--yes`** : refusé, bus non touché, **rien journalisé** (miroir du refus `can_inject` v0.1). → test Task 7.
- **Persistance de l'état sécurité entre invocations CLI séparées** (connexions distinctes) : lecture d'un DID protégé **échoue** avant déverrouillage, **réussit** après, et **ré-échoue** après retour en session *default* (qui re-verrouille). C'est la simplification assumée §5.6.1 — la **tester** pour qu'elle soit intentionnelle. → tests Task 3 et 7.
- **Service inconnu / DID inconnu / longueur invalide** : l'ECU renvoie le **NRC correct** (`serviceNotSupported 0x11`, `requestOutOfRange 0x31`, `incorrectMessageLengthOrInvalidFormat 0x13`) et **ne plante pas**. → tests Task 3.

## Contrat de l'ECU simulée (référence partagée par toutes les tâches)

Valeurs exactes que l'ECU (Task 3) **et** les tests des adaptateurs supposent. Toute tâche cliente code contre cette table.

**Identité / état initial**
- `req_id` (rx de l'ECU) = `0x7E0`, `resp_id` (tx de l'ECU) = `0x7E8`, 11-bit normal.
- Session au démarrage : **default** (`0x01`). Sécurité : **verrouillée**.

**Services et comportement**

| SID | Service | Comportement | NRC si refus |
|---|---|---|---|
| `0x10` | DiagnosticSessionControl | sous-fonctions `0x01` default, `0x03` extended. Passer en default **re-verrouille** la sécurité. | `0x12` subFunctionNotSupported (autre sous-fonction) |
| `0x3E` | TesterPresent | sous-fonction `0x00` → réponse positive. | `0x12` |
| `0x27` | SecurityAccess | niveau 1 : `0x01` requestSeed → renvoie le seed (4 octets) ; `0x02` sendKey → compare à `ExampleSeedKey.key_from_seed(seed)`. Bon → déverrouille. **Requiert session extended.** | `0x7F` serviceNotSupportedInActiveSession (si session=default) ; `0x24` requestSequenceError (sendKey sans requestSeed) ; `0x35` invalidKey (clé fausse) |
| `0x22` | ReadDataByIdentifier | `0xF190` (VIN) lisible **toujours** → ASCII fixe. `0x1234` (protégé) lisible **seulement si déverrouillé**. | `0x31` requestOutOfRange (DID inconnu) ; `0x33` securityAccessDenied (DID protégé verrouillé) |
| `0x19` | ReadDTCInformation | sous-fonction `0x02` reportDTCByStatusMask → liste de DTC préchargée filtrée par masque. Lisible toujours. | `0x12` (autre sous-fonction) |
| `0x14` | ClearDiagnosticInformation | vide le magasin de DTC. **Requiert déverrouillé.** | `0x33` securityAccessDenied (si verrouillé) |
| autre | — | — | `0x11` serviceNotSupported |

**Jeu de données préchargé (défauts, configurables)**
- VIN `0xF190` = `b"CARBONSIMECU00001"` (ASCII).
- DID protégé `0x1234` = `b"\xDE\xAD\xBE\xEF"`.
- DTC : `[(0x010203, 0x24), (0x040506, 0x2F)]` (code 3 octets, status 1 octet).
- Seed par défaut (test) = `b"\x11\x22\x33\x44"` (configurable).

- Algo (documenté dans le docstring, pour que le débutant le reproduise) : soit `n = len(seed)*8` bits ; `x = int.from_bytes(seed, "big")` ; `x ^= (mask & (2**n - 1))` ; `x = ((x << rotate) | (x >> (n - rotate))) & (2**n - 1)` (rotation gauche sur n bits) ; `return x.to_bytes(len(seed), "big")`. Déterministe, de longueur égale au seed.

**Interfaces:**
- Produces :
  - `class UdsError(Exception)` (base) ; `class UdsTimeoutError(UdsError)` ; `class UdsConnectionError(UdsError)`.
  - `@contextmanager def open_uds_client(channel: str, interface: str = "socketcan", *, rxid: int = 0x7E8, txid: int = 0x7E0, timeout: float = 1.0) -> Iterator[udsoncan.client.Client]` — ouvre le bus via `carbon.can.bus.open_bus`, monte un `isotp.CanStack` (adresse `Normal_11bits`, txid/rxid), une `udsoncan.connections.PythonIsoTpConnection`, et un `udsoncan.client.Client` configuré : `exception_on_negative_response=True`, codec DID générique « brut » (toute DID → octets bruts), timeouts bornés par `timeout`. À la sortie : ferme la connexion et `bus.shutdown()`. Les échecs d'ouverture/transport → `UdsConnectionError` ; `BusUnavailableError` de `open_bus` est laissé remonter (déjà un `BusError` parlant) **ou** ré-emballé en `UdsConnectionError` — choix de l'implémenteur, à documenter.

- Consumes : `carbon.can.bus.open_bus`, `BusError`/`BusUnavailableError`.

> **Note d'intégration (risque)** : l'API `udsoncan` ↔ `isotp` varie selon les versions (`CanStack` vs `NotifierBasedCanStack`, signature de `Client`, nom `interface=`/`bustype=` de python-can). ## Task 3: ECU simulée (répondeur ISO-TP/UDS)

**Files:**

**Interfaces:**
- Produces :
  - `@dataclass class EcuConfig` — `req_id=0x7E0`, `resp_id=0x7E8`, `seed: bytes = b"\x11\x22\x33\x44"`, `vin: bytes = b"CARBONSIMECU00001"`, `protected_did: int = 0x1234`, `protected_value: bytes = b"\xDE\xAD\xBE\xEF"`, `dtcs: list[tuple[int,int]] = [(0x010203,0x24),(0x040506,0x2F)]`, `algo: SeedKeyAlgorithm = ExampleSeedKey()`.
  - `class SimulatedEcu` construit avec `(channel: str, interface: str = "socketcan", config: EcuConfig | None = None)`.
    - `start(self) -> None` : ouvre le bus (via `open_bus`), monte un `isotp.CanStack` (miroir : tx=`resp_id`, rx=`req_id`), lance le **thread** de boucle, et **bloque jusqu'à ce que le récepteur soit attaché** (positionne un `threading.Event` `ready`, exposé en attribut) avant de rendre la main.
    - `stop(self) -> None` : arrête proprement le thread et `bus.shutdown()`. Idempotent.
    - Support du gestionnaire de contexte (`__enter__`/`__exit__` → start/stop) pour les tests.

L'état (session courante, verrouillé/déverrouillé, seed émis, magasin DTC) vit dans l'instance et **persiste entre les requêtes** (connexions client successives) jusqu'à un retour en session default ou un stop.
- Consumes : `carbon.can.bus.open_bus`, `carbon.uds.seedkey.ExampleSeedKey`, `carbon.uds.connection.open_uds_client` (dans les tests).

> **Implémentation** : la boucle lit les PDU UDS bruts depuis le `CanStack` (poll borné + `ready` event), décode `service + data`, met à jour l'état, et renvoie soit une réponse positive (`SID+0x40 ...`) soit un NRC (`0x7F SID NRC`). Pas d'usage d'un serveur udsoncan (il n'existe pas) : traitement **au niveau octet**, ce qui donne le contrôle total des NRC. Décomposer en méthodes `_handle_session`, `_handle_security`, `_handle_read_did`, `_handle_read_dtc`, `_handle_clear_dtc`, `_handle_tester_present`, `_negative(sid, nrc)` pour que chaque service soit testable et lisible.

## Task 4: Adaptateur `uds_scan`

**Files:**
- Create: `carbon/tools/uds_scan.py`
- Test: `tests/tools/test_uds_tools.py` (créé ici ; étendu Tasks 5-6)

**Interfaces:**
- Produces : `class UdsScan(Adapter)` — `name="uds_scan"`, `destructive=False`.
  `run(self, channel="vcan0", interface="socketcan", rxid=0x7E8, txid=0x7E0, **_) -> ToolResult`.
  Balaye un jeu de SID par défaut (au moins `{0x10,0x11,0x14,0x19,0x22,0x27,0x3E}`), classe chacun **supporté** (réponse positive ou NRC ≠ `0x11`) vs **non supporté** (`NegativeResponseError` code `0x11`). `data = {"supported": [hex...], "unsupported": [hex...]}`, `summary` = nombre de services supportés. Utilise `open_uds_client` + `uds_errors` ; une panne transport lève `UdsError` ; les NRC sont **attrapés localement** pour classer, jamais propagés.
- Consumes : `carbon.uds.connection`, `carbon.core.adapter.Adapter`, `carbon.core.result.ToolResult`.

> Détail : « supporté » = le service existe sur l'ECU. Un service qui répond `0x7F SID 0x11` est non supporté ; tout autre NRC (p. ex. `0x7F` en session, `0x12` sous-fonction) prouve qu'il **existe** → supporté. Envoyer une requête minimale/inoffensive par SID (p. ex. TesterPresent `0x3E 0x00`, session `0x10 0x01`…). Ne **pas** envoyer `0x14` (clear) de façon destructive pendant un scan : utiliser une sonde qui provoque un NRC sans effacer (p. ex. longueur volontairement invalide → `0x13`, qui prouve l'existence sans vider les DTC). Documenter ce choix.
